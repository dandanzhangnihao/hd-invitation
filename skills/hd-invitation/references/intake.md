# 制作前需要的资料

先读取用户附件，只问缺失或互相冲突的必要信息。可直接提供 Word/PDF、文字与素材图片，不要求将文档再手抄进表格。默认采用柔和中蓝定稿风格，资料齐全即可制作。

## 基本资料

| 资料 | 具体内容 | 缺失时处理 |
|---|---|---|
| 活动名称 | 正式名称、必要副标题、届次/期次 | 必需，不自拟正式名称 |
| 日期地点 | 日期、时间、会场及地址，或线上形式 | 必需；日期与星期冲突时确认 |
| 邀请正文或完整日程 | 活动介绍；日程版给每段时间、课程/事项、讲者姓名及单位 | 日程不擅改顺序或补课程；无讲者的活动无需强加讲者 |
| 主办及承办 | 各机构的准确全称与角色；协办等按实际需要 | 未提供则不编造，不继承参考图机构 |
| 品牌素材 | 希望展示的原始 logo，优先透明 PNG/SVG/PDF；多个标识的关系 | 需要 logo 却缺素材时补问；不需要 logo 可仅用机构名 |
| 报名方式 | 原二维码或报名链接；也可明确无需报名或先留空框 | 不生成假码；原码原样贴入并验证扫码 |

## 按需提供

- 主持人：只有已经确认的人选才提供姓名及单位；尚未邀约或未提供时不显示主持栏。
- 费用与规则：价格、名额、班级区别、合报/单报限制、自备设备、报名后变更规则。
- 学分/证书：项目编号、类型、分值、资格条件、审核要求、重复领取限制。内容不明确时先补问，不推断政策。
- 联系方式：姓名、电话、联系时间；交通住宿说明如需显示一并提供。
- 单位/城市照片：如希望底部显示真实建筑、招牌或地标，提供相应素材；缺失则用通用抽象装饰。
- 用途：默认竖版电子长图；需印刷时提供成品物理尺寸，以便确定像素需求。
- 特殊要求：必须逐字保留的文案、品牌规范、与默认风格不同的明确要求。

## 项目内的内容记录

建立 `content.json` 与逐行 `copy.txt`，记录标题、日期地点、分组日程、讲者数组、已确认主持人、说明、费用、学分、联系人、机构角色、素材来源及报名方式。保持用户最后一次明确修改为准，缺项不编造。多位讲者作为数组保存，显示时默认只用一个“讲者：”标签。

建立 `design-spec.json`，记录 `style_id: soft-medium-blue`、实际颜色、画布尺寸、版式、字体层级、品牌素材位置以及用户本次覆盖的要求。不建立等待配色选择的状态。图片修改前同步文案；不要要求用户操作这些内部文件。
